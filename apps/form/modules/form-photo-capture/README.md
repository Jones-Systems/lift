# Form photo capability boundary

This local Expo iOS module includes default-disabled AVFoundation camera source and an opaque lease boundary. Its fixed source guard is false: `availability()` returns `ready: false` / `native_capture_unqualified`; permission status/request report unavailable/unqualified, and acquire/capture/preview/retake/native display reject. `cancel(lease, originalScope)` returns the supplied lease ID with `unknown`. Compilation and execution are unproved.

The guarded engine source uses a dedicated serial AVFoundation queue, exact account/generation leases, rear wide-angle photo capture and native Data buffers limited to two 24 MiB front/side frames. It schedules a 60-second lease deadline and 15-second capture-response deadline on that queue; these are source intentions, not guaranteed wall-clock limits, because startRunning/stopRunning can block the same queue. Native blocking calls and delegate retirement still need device evidence; timeout cannot prove release. Lifecycle invalidates before queued cleanup. Late frames are fenced and never emitted as bytes or paths; cancellation while a delegate is outstanding remains unknown until terminal completion. Reference release is not forensic erasure.

The source calls no file-write, Photos-library, upload or logging API. Guarded permission source uses an explicit request with original shell/body/purpose scope; acquisition requires existing camera authorization and a nonempty NSCameraUsageDescription and never prompts implicitly. The false guard prevents any permission probe/request or camera/image operation. An OS prompt/answer may outlive Form's scope; stale callbacks grant no Form authority. Root owns permission-button binding, usage description and READY consumer/UI wiring. No phone/cache/vendor/backup/deletion/no-save guarantee follows, and all actual qualification flags stay false.

Production lifecycle callers inject WS01's existing cryptographic commandKey generator. Each request keeps its original creator nonce; native acquisition adds its own operation UUID. Exact original scope is required for cancellation, including released-operation idempotence. Acknowledgement-free cleanup preserves the original creator descriptor; acknowledged cleanup additionally matches the native operation UUID. Missing generator or creator identity has no production counter fallback. Only explicit synthetic fake ports accept counter IDs and leaseId-only acknowledgements.

Permission cleanup is independent of camera release. The synchronous permissionRetirement port reads a locked original requestId/scope witness: not_requested only from an actual no-OS-dispatch branch, retired only from the original OS callback, otherwise unknown. Promise rejection or settlement never proves OS retirement. State and frozen cleanup preserve original unknown permission custody even with no camera lease; no automatic retry or OS-dialog cancellation is supplied.

The TS adapter and injected port contract are in `../../src/body/capture/`. They use the same local-module/config/podspec pattern as FormSpeech, but leave binding and root lifecycle integration with WS01. No permission plugin or app configuration change is included. WS01 must inspect autolinking on the reconciled candidate before adding any runtime binding or feature call. This module remains unavailable after binding. Native acquire/capture require original shell/body/purpose scope and reject missing/mismatched scope. Optional guidance fallbacks cannot bypass this requirement. Raw bridge registration must not bypass original captured auth/session guards.

The bare native image ref producer accepts only exact opaque preview tokens and original scope. ImageIO downsamples to a verified output no larger than 1024×1024 pixels before UIImage construction; this resource bound proves no actual RSS/cache behavior or image quality. Synchronous token invalidation uses a separate lock and does not wait for camera start/stop. Late setters are fenced; already attached image hiding runs on the main queue and has no proved wall-clock bound. Selected-view retake drops obsolete content before replacement, preserves the other view on terminal failure and never restores the old preview. Native memory, rendering, cache and erasure remain unqualified. No screen, mount, review/finish, retained storage or derived assessment is supplied.

See [the integration and qualification spec](../../../../docs/body/native-capture/spec.md) for the exact seam, affected checks and missing evidence. [Expo's module API](https://docs.expo.dev/modules/module-api/) supplies the definition and AsyncFunction source pattern; Expo declaration/compiler and device execution have not been checked in this lane.
