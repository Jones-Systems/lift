# Agent guidance in Lift

Lift owns its application-specific working agreements. Shared working methods
and reusable agent roles come from the approved user-scope delivery for the
current provider and account. This keeps shared updates independent of Lift's
product commits while preserving local instructions.

## Startup and evidence

1. Read AGENTS.md and its required local guides. Claude readers enter through
   CLAUDE.md; both entry points lead to the same Lift policy.
2. Follow the shared startup bridge supplied by the host's provider instructions.
   Read the exact immutable guidance snapshot it selects, then only the supporting
   guidance and skills triggered by the task. Do not substitute a private source
   checkout's mutable HEAD or a copied root file for the delivered snapshot.
3. When currency matters, use the installed delivery system's supported read-only
   readiness/status route for the actual registered consumer. Keep source,
   installed files, delivery currency and native provider discovery as separate
   evidence. A local role file alone does not prove the role is callable. Do not
   invent a consumer ID, source revision, configuration home or readiness result.
4. If required delivery is missing, stale, drifted or ambiguous, report that
   condition and hold work that depends on it. Independent bounded inspection may
   continue. Use the owning host rollout/recovery process; this repository's
   instructions do not authorize installation, enrollment, global-file changes
   or provider restarts.

Host delivery must be installed and qualified separately for each provider,
account and host. New conversations use the instructions their provider actually
loads; running conversations retain their existing context. A merged Lift guide
is not evidence of live automatic delivery or fleet coverage. The shared rollout
may still be in progress on a given host.

## Ownership and updates

| Change | Owner and route |
| --- | --- |
| Shared working methods, instructions and shared-method skills | Codex V3 source; its approved export and immutable host-delivered snapshot. |
| Reusable agent definitions and shared-role policies | Universal Agents source; its generator and approved provider delivery. |
| Lift policy, application-specific roles or skills, and product code | Lift PR under this repository's working agreements. Product changes also require the matching private Form PR. |
| Delivery installation, source enrollment, provider bindings and schedule | The owning host-delivery workstream with its own scope and qualification. |

Do not add a second shared-method pin, copied shared instruction tree or
hand-maintained shared-role definitions to Lift. Keep host paths, delivery state,
account configuration and private source outside this public repository.
Application-specific roles and skills remain application-owned. If a future
change deliberately introduces tracked shared-role compatibility copies, use the
owning delivery system's generated copy lock and refresh-PR process. Such copies
can shadow user-delivered roles; verify that boundary instead of assuming global
updates replace them.

## Paired product work

Lift drives routine code changes and hosted public checks. Follow
PAIRED-DEVELOPMENT.md to open and maintain the matching Form PR, copy only the
scoped public-safe product delta, and obtain fresh Form verification after both
Lift workflows finish. Form retains private research and documents. Shared host
guidance delivery does not synchronize product branches or rerun paired checks.

Before integrating a feature, preserve its existing draft, dependency, review and
acceptance holds. Passing public checks or receiving new shared guidance does not
release those holds. Repository-only guidance changes do not create a product
parity claim; keep private Form's own application instructions with its owner.
